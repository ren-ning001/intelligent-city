# 策略：面向城市旅游的多景点路径规划与游览顺序优化

## 1. 总体策略

本项目面向城市旅游中的“一天内连续访问多个景点”场景，研究如何在给定起点和景点集合的条件下，综合考虑真实道路网络的通行代价，自动确定较优的景点访问顺序，并将各段道路最短路径拼接为完整行程，在地图上进行可视化展示。

项目采用“**开放数据驱动、路网建模为基础、访问顺序优化为核心、精确算法与启发式算法对照、地图可视化验证**”的总体策略。实验数据初步选用 OpenStreetMap（OSM）道路网络和景点 POI；在道路网络上计算景点间的实际通行代价，构建景点距离矩阵，再在矩阵上求解开放式旅行商问题（Open-loop Traveling Salesman Problem，开放环 TSP）。最终不仅比较不同算法输出的访问顺序，还将顺序映射回道路网络，形成连续的可视化游览路线。

项目优先完成不要求返回起点的基本模型，以控制实现复杂度并保证核心问题可评估。若时间和数据条件允许，再对距离与预计通行时间两种代价口径进行对照；景点开放时间、游客偏好、实时拥堵、多交通方式等复杂约束不作为首要实现目标。

总体流程如下：

1. 获取并固定实验区域的 OSM 道路网络与景点 POI 数据；
2. 清洗道路网络、筛选景点，并检查连通性和数据质量；
3. 将起点和景点坐标映射到道路网络，计算路网最短距离或预计通行时间；
4. 构建并缓存起点与景点之间的代价矩阵；
5. 使用最近邻算法生成初始访问顺序，并使用 2-opt 尝试改进；
6. 在小规模实例上使用 Held-Karp 动态规划获得精确最优解，作为算法效果的参照；
7. 比较路线总代价、相对差距和计算时间，并分析不同代价口径带来的差异；
8. 拼接各段道路最短路，在地图上展示访问顺序、路线几何和统计信息。

## 2. 预测策略

本节提出的是后续实验需要检验的研究假设。具体结果取决于实验区域、景点分布、道路网络质量、权重设定和算法实现，不能在实验前直接视为已证实结论。

### 2.1 路网距离与直线距离的差异

**预测 P1：** 景点间的路网距离通常不小于其平面直线距离；当道路网络存在绕行、河流或其他空间阻隔、单行道以及道路连接限制时，两者的差距可能更加明显。

**验证方法：**

- 对相同的起点和景点对，分别计算平面直线距离与道路网络最短距离；
- 统计路网距离与直线距离的比值、绝对差值及其分布；
- 选取差异较大的景点对，在地图上检查其道路连接和绕行情况；
- 说明坐标投影、POI 到道路网络的映射方式可能带来的误差。

该实验用于说明为什么访问顺序优化应以真实路网代价为基础，而不应直接用直线距离代替实际出行成本。若部分样本的比值异常，需要优先排查坐标投影、景点吸附和路网连通性问题。

### 2.2 启发式算法与精确算法的效果差异

**预测 P2：** 最近邻算法能够以较低计算成本快速生成可行路线，但其结果不一定接近全局最优；在最近邻初始解上执行 2-opt 后，路线总代价有望进一步下降。

**验证方法：**

- 在景点数量较小的实例上运行 Held-Karp 动态规划，获得精确最优代价；
- 对同一实例运行最近邻算法和最近邻加 2-opt 算法；
- 计算启发式路线相对于精确最优路线的差距：

\[
\operatorname{Gap}(\%) =
\frac{J_{\text{heuristic}}-J_{\text{optimal}}}
{J_{\text{optimal}}}\times 100\%
\]

- 记录 2-opt 优化前后的总代价与运行时间，检查其是否带来实际改进；
- 在不同景点数量或不同 POI 子集上重复实验，观察结果的稳定性。

若 2-opt 后的代价没有下降，应检查邻域搜索的终止条件、访问顺序更新逻辑，以及非对称路网下反转子序列所引起的内部边方向变化。由于道路网络的距离矩阵可能不对称，不能未经验证直接套用对称 TSP 的两边增量公式。

### 2.3 景点数量与计算时间的关系

**预测 P3：** 随着景点数量增加，精确算法的计算与存储开销将迅速增长；最近邻等启发式方法更适合较大规模实例，但其解的质量需要通过基准实验衡量。

**验证方法：**

- 在相同道路网络和相同代价矩阵生成规则下，设置若干不同规模的景点集合；
- 记录 Held-Karp、最近邻和最近邻加 2-opt 的运行时间；
- 在可完成精确求解的规模内，比较各启发式算法与精确解之间的差距；
- 将距离矩阵计算时间与访问顺序优化时间分开记录，避免把路网预处理成本误认为 TSP 求解成本；
- 对较大规模实例，重点报告启发式算法的运行时间、总代价及其相对基线的改进。

Held-Karp 的理论时间复杂度为 \(O(n^2 2^n)\)，空间复杂度为 \(O(n2^n)\)；最近邻的时间复杂度为 \(O(n^2)\)。2-opt 每轮邻域检查通常为 \(O(n^2)\)，整体耗时还取决于改进轮数和实现方式。因此，实验预期会体现精确算法与启发式算法在解的质量和计算效率之间的权衡，但具体可处理规模应由实际运行结果确定。

### 2.4 距离最优与时间最优路线的差异

**预测 P4：** 将路段长度作为权重和将预计通行时间作为权重，可能得到不同的最优访问顺序与路线。

**验证方法：**

- 在同一张道路网络上分别构建距离权重和时间权重；
- 时间权重暂按“路段长度除以按道路等级估计的速度”计算，并明确记录速度赋值规则；
- 分别计算两种口径下的代价矩阵并运行相同的顺序优化算法；
- 对比访问顺序、总路程、预计总时间和路线空间形态；
- 分析差异是否与道路等级及其速度假设有关。

这里的预计通行时间是基于道路等级与速度假设的模型估计，不等同于实时导航系统提供的交通预测。若两种权重得到相同或近似的顺序，也应如实报告，而不应为了符合预期而强行解释出差异。

### 2.5 数据质量与坐标映射对结果的影响

**预测 P5：** 路网连通性、POI 筛选质量以及景点坐标映射方式会影响距离矩阵的可靠性，并可能进一步改变最优访问顺序。

**验证方法：**

- 检查路网中的孤立子图、不可达节点和单行道方向信息；
- 对景点 POI 进行去重、类别筛选与人工核对；
- 记录每个景点坐标与映射道路节点之间的空间距离；
- 对无法到达或映射距离明显异常的景点进行排查；
- 若时间允许，对“最近路网节点”与“最近道路边上的投影点”两种映射方案进行小规模对照。

若不同映射方案导致总代价明显变化，应将其作为模型误差来源报告，并说明最终采用的处理方案及适用范围。

## 3. 技术策略

### 3.1 数据获取与预处理

**数据来源：** 使用 OpenStreetMap（OSM）道路网络与景点 POI。数据可按目标区域边界或中心点加半径获取，也可使用 Geofabrik 提供的离线区域数据文件。所有实验应保存本地数据快照并固定版本，以保证不同算法使用相同输入、实验能够复现。

**道路网络处理：**

- 将道路网络抽象为带权有向图 \(G=(V,E,w)\)，其中节点表示道路交叉口或路段端点，有向边表示可通行路段；
- 根据道路标签处理单行道、禁行信息和道路方向，避免将真实有向路网错误地视为无向图；
- 检查道路拓扑与连通性，识别孤立子图，并依据实际道路可达关系处理不可达节点；
- 在报告中明确道路类型筛选规则及任何必要的通行假设。

**景点 POI 处理：**

- 按 `tourism`、`historic`、`leisure` 等相关 OSM 标签制定明确筛选规则；
- 保留名称、类别、经纬度等必要字段；
- 对重复 POI、缺失坐标、名称或类别异常的记录进行清理；
- 对筛选结果进行抽样或人工核对，减少不符合实际游览场景的点位。

OSM 具有开放和可复现的优势，但其众包数据也可能存在拓扑错误、信息缺失和 POI 标注不一致等问题，因此数据清洗应作为独立步骤，而不是直接把原始数据输入算法。[2][3][5][8]

### 3.2 景点坐标映射与路网建模

景点通常不直接位于道路网络节点上，需要将起点和景点坐标映射到路网。基础实现采用最近路网节点映射（snap），并在局部平面坐标系下计算空间距离，避免直接使用经纬度欧氏距离作为精确的平面距离。

设映射函数为 \(\sigma(x)\)，则景点间的路网代价由其映射节点之间的最短路代价近似得到：

\[
d(u,v)=\min_{\mathcal P\in\Pi_{uv}}
\sum_{e\in\mathcal P}w(e)
\]

其中 \(\Pi_{uv}\) 为从 \(u\) 到 \(v\) 的可行道路路径集合。由于道路网络可能具有单行道和方向限制，一般不能假定 \(d(u,v)=d(v,u)\)。

实现时应保存每个 POI 的原始坐标、映射节点及映射距离，便于定位异常结果。如果最近节点映射造成明显绕行或误差，且实现时间允许，可进一步尝试最近道路边投影。该改进属于可选方案，不应在尚未实现或验证时作为既定功能描述。

### 3.3 最短路径计算与代价矩阵构建

本项目将最短路径计算与访问顺序优化分离：先计算任意两个相关地点之间的路网代价，再在代价矩阵上优化景点访问顺序。这样可以让多种顺序算法共享相同的输入，保证比较公平。

**距离权重：** 将每条道路边的长度作为权重，优化目标为总路程最短。

**时间权重：** 在道路长度基础上，根据道路等级设置估计速度，以“长度 / 估计速度”作为边权，优化目标为预计总通行时间最短。速度赋值属于模型假设，应在实验记录中明确说明。

**计算方法：** 对起点及各景点映射后的节点分别运行 Dijkstra 单源最短路算法，从结果中提取其他目标点的最短路代价，形成矩阵：

\[
D_{ij}=d(\sigma(s_i),\sigma(s_j))
\]

其中下标 \(0\) 表示起点，其余下标表示景点。若路网为有向图，应保留矩阵的非对称性；对不可达的点对不能擅自赋予普通有限距离，应先排查数据、连通性和映射问题，再明确处理方式。

为减少重复计算，应将计算完成的代价矩阵缓存到本地。比较不同访问顺序算法时复用同一矩阵；比较距离与时间口径时，则分别生成并保存对应矩阵。文献指出，真实道路网络上的最短路算法表现与网络结构、实现方式和规模有关；在本项目的中等规模实验中可优先采用 Dijkstra，在计算规模显著扩大时再评估预处理或加速算法的必要性。[2][5][8]

### 3.4 访问顺序优化：精确解与启发式解结合

项目将访问顺序建模为固定起点、无需返回起点的开放环 TSP。给定景点集合 \(S=\{s_1,\ldots,s_n\}\)，访问顺序为排列 \(\pi\)，目标函数为：

\[
J(\pi)=d(\sigma(s_0),\sigma(s_{\pi(1)}))
+\sum_{k=1}^{n-1}
d(\sigma(s_{\pi(k)}),\sigma(s_{\pi(k+1)}))
\]

求解目标为：

\[
\pi^\ast=\arg\min_{\pi}J(\pi)
\]

采用以下组合策略。

#### 3.4.1 Held-Karp 动态规划：小规模精确基准

对小规模景点集合，采用 Held-Karp 动态规划求解最优开放式访问顺序。状态 `dp[T][j]` 表示从起点出发，访问景点子集 \(T\)，并以景点 \(j\) 结束时的最小总代价。初始状态为：

\[
dp[\{j\}][j]=D_{0j}
\]

状态转移为：

\[
dp[T][j]=
\min_{i\in T\setminus\{j\}}
\left(dp[T\setminus\{j\}][i]+D_{ij}\right)
\]

最终取 \(\min_{j\in S}dp[S][j]\) 作为开放行程的最优代价，并通过回溯恢复访问顺序。该算法用于小规模基准，而不作为所有规模的默认算法。其理论来源为 Held 与 Karp（1962）[4]。

#### 3.4.2 最近邻算法：快速生成初始解

从起点出发，每一步选择距离当前位置最近且尚未访问的景点，直至所有景点均被访问。最近邻算法实现简单、计算成本较低，可作为启发式基线和 2-opt 的初始解。

其局限在于局部贪心选择可能导致后续出现较长路段，因此不能将最近邻结果直接视为全局最优。Sengupta 等（2018）报告了最近邻策略在开放环 TSP 实例中与最优解之间存在明显差距的情况，为本项目开展定量比较提供了参考。[1]

#### 3.4.3 2-opt 局部搜索：改进访问顺序

在最近邻生成的访问顺序上执行 2-opt，尝试通过反转访问序列中的一段子序列来降低总代价，直至找不到能够进一步降低目标函数的交换，或达到预设的计算限制。

实现时必须特别处理**非对称距离矩阵**：道路网络中的单行道和方向限制可能导致 \(D_{ij}\ne D_{ji}\)。反转子序列不仅改变两条边界边，也会改变被反转片段内部各边的方向。因此，程序应按真实方向重新计算受影响部分的代价，或采用经过验证的适用于非对称 TSP 的增量计算方式，不得直接照搬对称 TSP 的经典两边增量公式。

本组 8 篇调研文献没有直接研究 2-opt 的论文。因此，本项目将 2-opt 作为计划采用的局部改进算法，并通过实现测试和实验结果验证其有效性；如正式报告需要严格论证其算法原理，应另行补充对应的原始文献。[1][6]

### 3.5 路线恢复与地图可视化

访问顺序优化输出的是景点编号序列，而非可直接展示的连续道路路线。为得到完整行程，需要根据访问顺序，逐段提取起点到第一个景点、相邻景点之间的道路最短路径，并按顺序拼接。

实现时需要：

- 检查各段路径是否可达；
- 拼接时处理相邻路径重叠的端点，避免重复节点导致几何线串异常；
- 检查整条路线是否连续，是否存在断裂或方向错误；
- 将路线与景点位置、访问序号一起展示；
- 展示总距离、分段距离，以及在时间权重可用时的预计通行时间；
- 在条件允许时支持起点和景点集合选择，并允许查看不同算法或不同权重口径的结果。

地图展示应服务于算法验证，而不仅是展示一条路线：用户应能从访问序号识别景点顺序，从路线几何观察绕行，并从统计信息比较不同方案。OSM 路由工程和 GIS 路线可视化研究为“距离表计算—TSP 顺序优化—路线呈现”的流程提供了参考。[3][7][8]

### 3.6 实验评价与对照设计

为避免仅凭地图观感判断路线优劣，项目将定量评价与可视化检查结合起来。

**核心评价指标：**

| 指标 | 含义 | 用途 |
| --- | --- | --- |
| 总路网距离 | 各段路线距离之和 | 比较距离权重下的路线成本 |
| 预计总通行时间 | 各段估计通行时间之和 | 比较时间权重下的路线成本 |
| 相对最优差距（Gap） | 启发式代价相对精确最优代价的百分比差距 | 评价小规模实例上的解质量 |
| 运行时间 | 距离矩阵计算与顺序优化分别计时 | 比较算法效率，区分预处理与求解成本 |
| 2-opt 改进幅度 | 最近邻优化前后代价的变化 | 检查局部搜索是否有效 |
| 路线可达性与连续性 | 各段是否可达、拼接后是否连续 | 检查数据和工程实现正确性 |

**对照组设置：**

1. 最近邻算法；
2. 最近邻 + 2-opt；
3. Held-Karp 动态规划（仅在可承受的小规模实例中）；
4. 距离权重与时间权重两种实验口径；
5. 在条件允许时，加入随机访问顺序等简单基线，用于说明算法相对朴素方案的改进程度。

在小规模实验中，以 Held-Karp 的最优解为主要参照；大规模实验不能直接声称获得全局最优，应报告可复现的启发式结果、运行时间和适当基线之间的差异。若使用最小生成树等下界估计差距，需要注意：实验背景中的相关论证针对对称情形，不能未经论证就将其直接用于非对称有向路网。

### 3.7 工程实现的风险控制

| 风险点 | 可能影响 | 处理策略 |
| --- | --- | --- |
| OSM 路网拓扑不完整或存在孤立子图 | 景点间不可达，距离矩阵出现无效值 | 检查连通性、映射节点和道路方向；必要时调整实验区域或清洗规则 |
| POI 重复、类别不合适或坐标异常 | 实验对象不准确，路线不具备实际意义 | 明确标签筛选规则，去重并人工核对 |
| 坐标映射误差 | 路网距离偏大或访问顺序发生变化 | 保存映射距离，抽查异常点；必要时比较最近边投影 |
| 距离矩阵重复计算耗时 | 实验效率下降 | 缓存矩阵，并在相同口径的算法比较中复用 |
| 有向路网下错误使用对称 2-opt 公式 | 目标函数计算错误，结果不可比较 | 对受影响的内部边方向重新计价，并用小规模测试验证 |
| 精确算法规模过大 | 内存或运行时间超出可接受范围 | 将 Held-Karp 限定为小规模基准，较大规模采用启发式方法 |
| 路线拼接产生重复节点或断裂 | 地图路线显示异常 | 校验相邻段端点、连续性和可达性 |
| 预计时间被误解为实时交通时间 | 结果解释失真 | 明确其来自道路等级速度假设，不声称包含实时拥堵 |

## 5. 策略实施原则与预期产出

本项目遵循以下实施原则：

1. **先保证基本模型正确，再扩展功能。** 首先完成固定起点、开放行程、基础道路权重下的访问顺序优化。
2. **所有算法共享一致的数据与代价矩阵。** 只有在输入和目标函数一致时，算法结果才具备可比性。
3. **用精确解验证启发式，而非只看路线图。** 在小规模实例中采用 Held-Karp 作为基准，以总代价、Gap 和运行时间评价算法。
4. **显式处理有向路网。** 不将单行道网络默认简化为对称矩阵，尤其注意 2-opt 的代价更新。
5. **区分预测、模型假设与实验结果。** 距离与时间的差异、启发式改进幅度和运行时间趋势均应由实验记录支持。
6. **控制扩展范围。** 多准则偏好、景点时间窗、实时交通和复杂元启发式作为后续方向，不挤占基础流程的实现与验证时间。

策略完成后，项目应能够产出：一套固定且可复现的 OSM 道路与景点数据；一个可计算路网距离或预计时间的代价矩阵模块；最近邻、2-opt 与小规模 Held-Karp 算法实现；一组可重复的算法对比实验记录；以及能够展示访问顺序、完整道路路线和统计指标的地图可视化结果。这些产出共同支撑开题阶段提出的研究问题，并为后续实施计划和课程报告提供明确的工作边界。
